# 内容、时长与自然口播

优先保证已确认口播稿、旁白和画面内容完整，保留用户已经优化并验证过的语速、音色、表情、动作与表演节拍。用户给出的普通时长是规划参考，不是必须凑够的数字。不能为了它拉慢或加快声音、拉伸动作、添加无意义停顿或填充内容。

## 时长模式

| 用户意思 | 处理方式 | 模式 |
| --- | --- | --- |
| “做 15 秒、45 秒、1 分钟”，没有强调硬性要求 | 用作大致内容规划参考；最终按稿件、旁白和镜头自然完成 | 默认 `reference`，可传 `--duration N` |
| 提供了完整或逐字锁定稿 | 保留内容，按已有自然语速估时；参考数字不强制补稿或删稿 | `reference` |
| 没有指定时长 | 按完整内容反推时长 | `reference`，不传时长 |
| 明确“最长不能超过 N 秒” | 保留自然语速，内容冲突时先讨论取舍 | `content-fit --duration N` |
| 明确“必须精确达到 N 秒”或已确认平台硬性要求 | 单独说明可行性与误差；仍不得用变速或拖延表演凑秒数 | `exact --duration N` |

新 CLI 与多模型 spec 默认 `reference`。旧 `auto`、`content-fit`、`exact` 合同保持原有含义，不静默改写已确认的任务、预算或脚本。用户后续修正旧项目的时长意图时，记录这次修正后再审核；不能伪造旧报告已通过。

## 内容规划

1. 先明确受众、核心信息、事实依据和已确认稿件。用参考时长估计大致内容量，但不为了靠近数字破坏内容或表现。
2. 沿用已确定的语速和角色表现。260 汉字/分钟只是在未提供既有设置时的估时默认值，本次规则修正不改变这个数值，也不改变角色、声音和表演模板。
3. 免费运行 `python3 scripts/workflow.py plan --script-file <草稿> --duration-mode reference --duration N`。它不联网、不生图、不生成声音；按完整句子估时并计算请求片段。
4. 参考时长与自然估时相差较大时，说明内容长度和预计结果，让用户了解方案；不要自动慢读、补空话或把预算一起扩大。每次付费仍受已确认片段数与费用上限约束。
5. 真正的硬性限制冲突时，再讨论修改内容或调整要求，不能为满足时长修改已经确认的语速、音色和表情动作。

## 分段

- 15 秒只是旧 Grok 网关单段上限；新模型按各自限制处理。
- 保持原有估时方法及每段约 0.6 秒起音收声余量，按接口支持的秒数取整。参考时长不会改变同一份稿件的自然分段或请求总长。
- 完整句子按顺序只出现一次，不在半句话处切分；模型装不下一句时，先在完整语义处调整内容或选择合适模型，不能简单加快语速。
- 参考模式不补满目标秒数。明确硬性 `exact` 模式仅在内容和自然表现可满足时安排请求，无法满足则说明限制；不生成长静音凑时长。
- 严格主音轨路线以原音轨和真实句子时间码分段，保留全部样本，不因参考时长而截断或拉伸音轨。

## 提示词和验收

维持原有角色声音设计和逐短语表演节拍。不能硬塞“第几秒说哪句话”的固定时间格；手势跟随实际语义，允许表情节拍不配手势。该规则修正不改写已有视频提示词。

先按原速完整看听首段，再在授权范围内继续。最终重点检查台词和旁白是否完整、声音与语速是否自然、人物表情与动作是否正常、口型与接缝是否协调。时长作为实际结果如实报告。

例如参考 45 秒、自然完成 41.917 秒：只要内容完整且实际看听通过，不因约 3 秒差异要求重新生成，更不能拉慢到 45 秒。技术解码或时长允许并不替代真实质量验收。长停顿统计仅作复核线索，不自动裁切句中停顿或变速。

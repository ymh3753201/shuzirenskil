# 全程无字生成与失败阻断（2026-11-06）

本规则来自用户明确要求，优先于历史文档的广告原生文字白名单。适用于所有新视频模型请求；已有视频、合同和失败报告不自动改写。

## 先检查素材与方案

- 生产参考图也必须无字：检查衣服、书脊、电脑/手机屏幕、包装、墙面、招牌、标识。不要只看人物脸部。看不清不能填“无字通过”。
- 新广告 `source_text=[]`。有字的真实商家招牌与全画面无字冲突时，先选择并确认不带字的实景构图/素材；不擅自删除品牌信息、换掉门店或将真实文字列成例外。
- 台词可以谈论字幕、数字或产品名，但视觉描述不能要求把它们显示出来。提示词冲突检查仅覆盖常见写法，不能代替 AI 阅读完整方案和看图。
- 方案与自备图片保持两次确认；本次技能审查不授权生成或重做。

## 请求编译

`text_policy.py` 为 workflow 与 studio 生成统一首尾约束。中文说明范围，英文明确这是无字摄影原片。完整台词只出现在 `<SPOKEN_AUDIO_ONLY>` 区块，标记本身也不朗读、不显示；表演触发短语保留在本地合同里，发送时改成原台词的字符位置，避免重复口号。字符位置用于语义动作同步，不是字幕编号或固定秒数安排。

视觉、服装、场景、镜头与动作字段发现“添加字幕”“显示标题”“写着某字”等冲突时本地拒绝，不自动删掉已确认的内容。请求超长直接拒绝，不截断末尾禁字规则。不要自行增添服务商未核实的 `negative_prompt`、关闭字幕等接口字段；本次不修改接口协议。

提交前检查实际待发送请求是否含完整约束；旧请求会提示先本地重新预检/准备，不能静默改写历史请求或重新 POST 已提交任务。已提交任务仍可查询与下载，质检失败不触发备用渠道。

## 原片与最终成片检查

1. 保留原片，先检查原始尺寸；例如 704×1280 不可冒充 720p。后期放大不能补足原片验收。
2. 连续制作使用 `inspect-production`；完整首段/最终验收使用 `workflow inspect-visuals` 或 `studio inspect`。所有新无字通过均须绑定逐帧 OCR 报告和画面清单。
3. 报告帧数必须等于实际解码帧数，覆盖真实首末帧；未完成、少帧、旧视频报告、被修改报告均阻断。
4. 实际查看所有取样及每个 OCR 疑似文字帧，填写 `reviewed_frame_indices`。OCR 没发现不等于无字证明，仍须真实完整视觉检查。小字、低置信度、外文、伪字不能自动忽略。
5. `text_qc_file`、`text_qc_sha256` 来自检查输出；若有疑似文字，逐项填写 `ocr_findings_review`，只有真实误检可用 `false_positive`，并写具体观察。不能复制模板、用低置信度解释真实文字。
6. 确认任何真实文字：`text_present=true`，说明时间、位置与内容，保存失败。禁止交付、继续生成、自动换渠道、遮挡或裁掉有效口播。两种历史失败文件名 `quality-failure.json` 和 `quality-failure-report.json` 都阻断执行。

完整验收仍包括原速看听、动作、口型、台词与接缝。OCR 不证明声音与动态自然；ASR（语音转文字）不同不等于真实发音错误。保留原识别，实听核对后再写证据。

静音尾巴只在无字及其他必要检查通过后，凭真实静音/语音时间码保守裁切。已有尾字保护继续有效；不得用裁尾把带字失败片变成合格片。内部停顿、语速和原片不改。

## 历史与边界

历史广告白名单验收函数保留以读取旧资料；新编译入口拒绝带白名单生成。旧审查记录缺少新逐帧字段时，对已有视频重新检查即可，不必重新生成。新授权的重做仍走原有独立版本与次数约束，不能把本次修复当成付费授权。

不能从提示词或单元测试推断“模型再也不会加字”。本地测试验证规则、请求内容、报告完整性和停止路径；模型服从率需要以后另行授权的真实样片验证。

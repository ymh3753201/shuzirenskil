# 交付质检清单

新规则见 `voice-casting-and-text-review.md`：每个原片和最终成片检查全片、全部取样和真实末帧，`no_generated_text=pass` 必须带绑定视频指纹的 `text_review`。首段先检查角色声线匹配；最终逐段对照首段实听并记录 `voice_casting_match` 和跨段一致性。


## 免费自动检查

- 每个计划片段有且只有一个下载文件。
- 成片包含视频流和音频流，时长大于 0。
- `exact` 时长项目的干净成片在确认误差内接近用户目标；内容模式接近稿件的自然时长，且包含每段余量和取整后的请求总秒数不超过用户上限。所有模式每段最多 15 秒，不检查是否“凑满 15 秒”。
- 输出比例、清晰度和片段顺序正确。
- 每段拼接前已检测尾部静音；超过 0.6 秒的部分已裁掉，只保留约 0.3 秒自然收尾。
- 最终成片末尾连续静音不超过 0.6 秒；若 Whisper 提供时间轴，最后一句结束到视频结束不超过 0.8 秒。
- 拼接过程没有使用淡入淡出或交叉转场。
- 拼接保持原片帧率；不同帧率先检查，不把 24fps 静默转为 30fps。
- 字幕或转写时间轴的结尾不能比视频结尾晚超过 0.25 秒；超出时人工听查末句是否被截断。
- 任务账本中每段提交次数不超过 1。
- 日志、合同和交付文件不含 API Key、Authorization 或图片 Base64。
- 请求模式没有混用 `image` 和 `reference_images`；多参考图的数量、顺序、职责和提示词标签一致。
- Files API 输入只来自用户确认图片，上传账本权限为 600 且设置自动过期；没有上传用户自己的音频文件。

## Codex 视觉检查

- 以正常速度完整播放每个原片和干净成片，检查真实动作连续性；抽帧不等于动态验收。
- 查看每段开头、中间、结尾和每个拼接点前后画面。
- 人物面部、发型、服装和主要场景没有不可接受的变化。
- 没有模型生成的字幕、乱码、Logo、水印、标题或 UI。
- 没有黑帧、长时间冻结、明显跳帧或错误镜头。
- 表情随句意自然变化，手势只在对应台词短语出现时轻微发生并自然回位；没有全程固定微笑、反复点头或僵硬悬停。
- 质检记录包含实际查看过的抽帧路径、文件指纹和逐项观察，不接受无依据的 `pass`。

## 语音检查

- 逐句看听人声与嘴部开合是否同步、手势是否在对应短语出现并回位、语调与语速是否自然；分别记录 `lip_sync`、`gesture_phrase_fit`、`motion_naturalness`、`voice_naturalness`、`normal_speed_playback` 的观察依据。
- 单独记录 `speech_pacing`：正常速度听完整片，检查是否因长停顿或慢读而显得拖沓。`review` 的静音统计会列出首尾、内部静音和超过 0.75 秒的停顿；统计只提示复核，不代替听感。对话题口播，若两处以上长停顿又无表达目的，标记失败，不得交付。
- Whisper 结果覆盖完整视频，没有异常长静音或开头结尾缺字。
- 数字、人物名、产品名、结论等重要内容与确认稿一致。
- 拼接点两侧都是完整句子，没有断音、叠音或重复台词。
- 使用预设声音时，实际听感与方案中的说话主体对应；不能只凭 `voice_id` 请求字段判定声音通过。
- 提示词生成人声的多段项目，逐段和逐拼接点实听性别听感、年龄感、音高、音色、语速、情绪和口音；必须写入 `cross_segment_voice_consistency` 证据并将 `--voice-consistency` 标为 `pass`。
- Whisper 转写只能证明“说了什么”，不能证明“是不是同一把声音”；不得用台词相似度替代跨段音色检查。
- 保存最终语音转写，并自动计算它与确认稿的相似度；差异过大时直接停止。

## 字幕检查（仅启用时）

- 干净版先通过全部检查。
- 字幕文字来自确认稿，Whisper 只提供时间参考。
- 字幕不遮挡人物面部，大小清晰，并处于安全区域。
- 字幕版没有新增未批准文字。

任何一项不通过都不得生成状态为 `pass` 的交付清单。Provider 画面缺陷不得自动触发第二次付费提交。

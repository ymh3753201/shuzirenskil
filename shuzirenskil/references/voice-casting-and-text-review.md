# 角色配音与文字策略：普通口播 3.0 / 广告 3.1

2026-10-18：首段所有观察项（包括 voice_casting_match、no_generated_text）必须使用包含 `status` 和 `observations` 的对象；旧纯文字不再视为通过。新模板为 `assets/pilot-review-template.json`。多模型的自由配音、参考音色与严格音轨规划见 `multimodel-production.md`，本文件其余内容描述现有 Grok 执行流程。

## 1. 先做配音选角，再锁定声音

图片能提供发型、服装、饰品、构图和场景等视觉事实。结合用户指定的角色、受众、语言与表达目的，AI 为角色选择一种声音。这是创作选择，不能声称从长相推断了真实声音、籍贯、性格、民族或真实年龄。用户明确的声音偏好优先。

方案阶段先设计 `voice_profile` 和 `voice_casting`；图片生成或用户图片绑定后，必须实际打开图片再核对。不要每次只把“男性”换成“女性”，其余都沿用“温暖、清晰、专业”。不同角色按表达需求设计差异；同一角色再次出现则优先复用已接受的档案，不随机轮换音色。

`voice_profile` 保留八项基础描述，音高和音色须具体。新增 `voice_casting`：

| 字段 | 含义 |
| --- | --- |
| character_key | 稳定的角色标识，不是服务商 voice_id |
| role | 本片角色职责与受众 |
| visual_basis | 方案阶段的造型设计依据，出图后用实际观察复核 |
| rationale | 为什么选择这个声音，注明创作选择 |
| resonance | 共鸣位置与厚薄，如前口腔明亮、胸腔适量支撑 |
| texture | 一至两个可听辨特征，如干净清亮、少量柔和气息 |
| articulation | 咬字力度和收尾习惯，避免规定每句话同一旋律 |
| avoid | 与角色不符的声音，如夸张播音腔、刻意卖萌 |

声音描述控制在少数相容特征内，不堆砌互相冲突的词，也不写未经声学校准的精确赫兹值。语速沿用实际文稿与时长规划，不能为了换音色任意变慢。

可用的选角思路（不是默认预设）：生活方式分享可选中音区、清亮偏薄、句尾轻收；沉稳的技术讲解可选中低音区、适量胸腔共鸣、重点词咬字清楚；轻快的活动主持可选明亮有弹性、少气声、语调变化更明显。性别相同仍能有区别；这些都不是根据发型或脸型得出的事实。

完整配音方案写入 `voice_signature`，各段直接复用同一个对象，不逐段重新写形容词。`voice_identity_signature` 单独记录基础身份描述，排除语速与情绪；它用于区分“身份特征”和“表达方式”，不是实际声纹。合同仍用完整声音方案指纹防止未经确认的改动。

## 2. 出图后核对，沿用原有第二次确认

1. `bind-generated-image`、`generate-image` 或 `bind-image` 完成后，读取 `project.json` 中的主图和所有生产参考图，实际查看。
2. 从 `assets/character-review-template.json` 建立观察文件，填入当前 `canonical_sha256`、`image_set_digest`、`voice_signature`。分别记录可见事实、声音选角匹配理由、所有参考图无文字检查。
3. 仅在实际匹配且参考图干净时将 `casting_fit` 和 `reference_text_free` 设为 `pass`。
4. 执行：

```bash
python3 scripts/workflow.py --project-dir <项目> review-character --evidence-file <角色检查.json>
```

向用户展示图片时，一并用一句易懂的话介绍声音设计，例如“中音区、清亮偏薄、轻松交流的女声；两段沿用同一组声音描述”。原定的“确认图片并开始制作”同时确认该已披露设计，不新增例行确认轮次。若图片明显偏离原定角色，应先处理差异；不要悄悄改已确认声音字段。实质改变声音方案须更新方案并确认。

`authorize` 和 `preflight` 都会核对图片与声音指纹。图片组或声音变化后，旧观察不能直接沿用。旧项目 2.0/3.0 合同保持可读，普通口播用 3.0，广告用 3.1；`--allow-legacy-performance-plan` 仅用于明确的旧方案迁移/离线兼容测试，不能作为日常生产省略选角的捷径。

## 3. 首段是后续声音的听感基准

新普通口播在方案中选定 `continuous_candidate` 时，按 `continuous-production.md` 区分继续制作检查与最终验收。以下真实听审要求用于最终合格结论；缺少主观看听能力不得逐段中断已授权制作。历史项目、广告及严格音轨仍用原完整关卡。

首段正常速度完整看听，记录 `voice_casting_match`：实际音高、声音质地、共鸣与咬字是否接近已确认选角。自然但不符合角色的声音也不能直接当作通过。`review-pilot` 记录试片文件指纹和声音方案指纹；剩余各段仍用相同声音描述和主图。

最终 `review --voice-casting-match pass --voice-consistency pass` 须有真实听感依据。逐段对照首段，再连续听每个接缝；说明音色是否一致，不能用音量接近、相同文本描述或 Whisper 识别正确替代听感。单段也要验收角色声音是否匹配。优先由具备实际视听工具的 AI 执行，不新增逐段制作确认。当前会话无法直接听音频时，先按 `automatic-quality.md` 运行本地音频质检，完成静音、真实转写、语音区间等可做的检查；仅将确实缺少能力的音色、自然度、口型等项目保留 `pending` ；连续候选制作时先完成全部已授权片段与剪辑，仅在最终候选片一次性说明需要补充的实际判断，不能把全部检查推给用户，也不能自动制造听过的证据。

文字描述是模型的软约束，不等于 voice_id 或声音克隆。当前 91topgo 路线不发送外部音频，不能把开源项目的“先生成整轨声音再驱动画面”直接套进来。未来只有在明确支持音频驱动的接口通过授权与实测后，才可增加该路线；不能静默换模型、加 TTS 或增加费用。

## 4. 无文字规则从输入到输出

以下全画面无字要求适用于 3.0 和白名单为空的 3.1。3.1 广告有原生招牌/包装文字时改按 `commercial-direction.md` 的白名单验收：角色阶段用 `reference_text_policy_pass`，视频阶段记录实际文字与 `source_text_matches`，不得把有招牌的素材谎报为无字。

生产参考图先检查文字、Logo、背景招牌；发现问题先处理或说明不能达到全画面无文字要求。3.0 提示词末尾由程序固定加入无文字画面规则，用户自定义 `negative_constraints` 不能将它删除：台词和动作触发词仅用于声音与表演，片尾保持同一人物和场景，不生成金句、标题或总结字卡。正式字幕仍仅在干净版通过后按用户要求本地制作。

禁止在画面、动作、连续性说明里同时要求“打出重点词/出现标题”。即使强制规则存在，模型仍可能违背，因此必须检查实际输出。

每个原片下载后、首段放行前、最终剪辑后都运行本地检查素材准备：

```bash
python3 scripts/workflow.py inspect-visuals --video <实际视频.mp4> --output-dir <独立检查目录> --boundary <可选拼接秒数>
```

命令免费、不联网。默认全程每半秒取一帧，最后两秒每四分之一秒取一帧，额外包含真实首末帧；拼接点可重复传 `--boundary`。按真实帧编号提取，避免按容器时长定位末尾时取不到图片。输出 `manifest.json` 记录视频指纹、帧号、时间、图片和图片指纹；命令只准备检查材料，不自动判定没有文字。

实际连续看完视频，再查看清单列出的全部取样，特别是最后一帧。将 `assets/text-review-template.json` 的 `text_review` 对象合入首段或最终质检证据。确实看过才填写 `full_video_viewed`、`all_sampled_frames_viewed`、`last_frame_viewed`，并记录真实检查者和具体观察。`text_present=false` 只能在没发现文字时填写。不要把所有图片堆成文字无法辨认的小缩略图后宣布通过。

`review-pilot` 必须提供 `no_generated_text` 说明和这份结构化证据。最终 `review --no-generated-text pass` 也需要该证据；清单、视频、取样文件任一变更都会要求重新检查。没看全时标记 `pending`，发现文字时标记 `fail`。取样可能漏掉瞬间闪字，所以不能省略连续查看，也不能把 OCR 未检出当作无文字保证。

OCR 疑似文字应由 AI 查看对应真实帧判断，不能直接断言合格或失败；确认无字的要求不允许协商放宽。发现真实文字，直接记录 fail，不问“是否允许保留这些字”。

若文字已在原片出现，不应静默遮挡、模糊、删掉含有效口播的尾段或付费重生成。保存失败预览和出现位置，说明可选修复范围，不要求先报价；此时不能生成通过的交付清单。后期裁剪后必须重新检查，因为无字原片末帧不代表裁剪后末帧无字。

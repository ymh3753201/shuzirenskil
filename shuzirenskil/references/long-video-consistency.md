# 长视频一致性方案

先阅读 `voice-casting-and-text-review.md`。3.0 按角色设计声音锚点，出图后实际核对，整个项目使用同一份声音档案；不要在不同分段自行改写。完整方案指纹用于防误改，身份指纹排除情绪和语速，它们都不是模型实际声纹。首段是后续实听基准，各原片和拼接后成片均须检查无文字。


## 先说明能力边界

当前 Provider 链首选 91topgo，参考图路线使用带货视频 Skill 已验收的 `reference_images` 合同。本 Skill 会把本地确认图压缩成 JPEG Data URI 后直接随 `/v1/videos` 请求发送，不依赖图片上传接口；MikuAPI 作为显式降级保留，不能在 91topgo 的付费 POST 后自动切换。参考图链路通过后，长视频连续性、声音稳定性和口型仍需逐条检查。

当前 MikuAPI 生产开关只启用 `grok-imagine-video-1.5` 的基础单图生视频合同。多参考图和预设声音仍等待中转站验收；Files API 已真实返回 HTTP 404；视频续写、1080p 和自有音频声音参考保持关闭。默认由模型按固定声音提示词生成口播人声，但这仍无法保证多段之间声音和口型完全一致。对声音一致性要求严格时，应停止多段付费制作，或把稿件压缩为一段。

xAI 官方最新资料确认原生 `reference-to-video` 最多使用 7 张参考图和 3 个预设声音，最高 720p；用户自己的音频文件仍是可信合作方申请能力。这些字段没有经过当前 MikuAPI 真实验收，所以不能因为官方支持就直接用于付费生产。

## 图片设计

1. 按方案选定的路线取得一张主参考图：Codex 内置生图、自备图片或第三方 `gpt-image-2`。固定人物身份、发型、服装、场景、机位、灯光和画幅。
2. 多段提示词生成人声默认必须直接使用同一张主参考图、同一 SHA-256 和同一个 Provider 地址。这同时减少换脸、换装和音色漂移，但每段动作会从相近姿态重新开始。
3. 只有用户明确接受人物和音色漂移风险时，才允许派生分段首帧。它必须从主参考图继续编辑，记录主图 SHA-256，并在绑定时显式使用 `--allow-derived-segment-images-with-risk`。
4. 分镜图用于向用户预览动作和构图，默认不发送给视频接口。它不能替代主参考图。
5. 多参考图模式下，按 `identity`、`wardrobe`、`product`、`scene`、`style`、`composition` 分配唯一职责；能用 2-4 张解决时不要凑满 7 张。
6. 正式绑定前检查图片能被解码、短边至少 512 像素，并且比例与最终视频一致，避免接口拉伸脸型。

## 提示词设计

所有分段重复同一组固定描述：参考图职责、人物身份、服装、场景、机位、灯光、动作范围和结构化声音特征。`voice_profile` 的 8 项方案值在项目内保持一致，并生成同一个 `voice_signature`；该指纹只防止提示词被误改。声音身份稳定，同时允许每句话的音高、语速和情绪自然起伏。各段依据自己的真实台词填写 `performance_beats`，在关键词处做少量语义相关的表情与手势，随后回位，不把人物固定为一张始终微笑的静态脸。

## 分段和拼接

- 每段不超过 15 秒，并在完整句号、问号或感叹号后结束。
- 先按 `duration-planning.md` 匹配内容与用户目标，再联合分配完整句子和每段秒数；15 秒只作上限，不强制每段补满。目标时长下尽量减少请求，句子边界确实要求更多片段时在方案中说明；短稿先修稿，不拖慢朗读。
- 句首和句尾留短暂停顿，拼接时使用直接切换，不在说话中做淡化或交叉转场。
- 每个项目生成 `continuity_signature` 和 `voice_signature`，所有分段必须共享同一组视觉约束和声音特征。
- 多段先提交首段试片，按正常速度完整看听并通过 `review-pilot`，才继续提交其余已授权片段；首段不自然就停止后续付费。
- 声音、口型和跨段动作风险必须写进第一次方案；用户第二次确认图片并开始制作时一并接受，不得另行要求第三次确认。
- MikuAPI 尚未验收的多参考图、预设声音、Files API 和视频续写字段不得进入付费请求；91topgo 的 `reference_images` 只按已记录的 URL/Data URI 合同发送。
- 质检必须查看每段开头、中间、结尾和拼接点两侧，用最终语音转写核对确认稿，并真实听每段的音高、音色、语速、情绪和口音，记录 `cross_segment_voice_consistency`；Whisper 不能代替这项听感检查。

## 官方资料与中转站的区别

- [xAI 模型页](https://docs.x.ai/developers/models/grok-imagine-video-1.5)：原生模型输入列出文字、图片和音频；价格按分辨率变化。
- [xAI 视频生成](https://docs.x.ai/developers/model-capabilities/video/generation)：原生时长 1-15 秒，生成视频默认带音轨。
- [xAI 图生视频](https://docs.x.ai/developers/model-capabilities/video/image-to-video)：支持 URL、Base64 或 Files API 图片，示例为 12 秒。
- [xAI 参考图生视频](https://docs.x.ai/developers/model-capabilities/video/reference-to-video)：原生最多 7 张参考图和 3 个普遍开放的预设声音；用户自己的音频文件仅向可信合作方申请开放。
- [xAI 视频续写](https://docs.x.ai/developers/model-capabilities/video/extension)：使用独立续写接口，输入视频 2-15 秒，续写部分 2-10 秒。
- 当前 MikuAPI 接入：使用 xAI 兼容的 `POST /v1/videos/generations`、单个 `image.url` 和基础生成字段；已完成 4 秒、480p、9:16 与 15 秒、480p、16:9 单图短片验证。15 秒单段成功不代表多段连续性已经通过。

资料核对日期：2026-08-24。生产时仍以中转站最新文档、能力开关和免费预检为准。

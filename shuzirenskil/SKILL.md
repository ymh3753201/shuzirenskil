# Shuzirenskil

把用户现有材料变成可检查、可确认、可追踪的数字人口播视频。先做好内容和视觉方案，再生成图片和视频；不要把主题、现成视频、外部音频和完整脚本当成同一种任务。

运行环境：Python 3.10+、FFmpeg/ffprobe；本地字幕可选安装 whisper-cli 和离线 Whisper 模型。

## 2026-10-24 rc6：自动质检、分段推进与完整环境准备

先读 `references/automatic-quality.md`。安装用 `scripts/setup_environment.py` 准备独立 Python 3.12、固定版本媒体/语音依赖和本地识别模型，随后 `scripts/run.py doctor --self-test` 实际验证；首次需要联网下载，不上传作品。不能把文件复制成功或依赖可导入当作实际语音识别已验证。

第二次确认已授权全部既定片段。首段和逐段质检是 AI 的执行工作，不得每段重新询问是否继续；首段真实验收通过后使用 `studio advance` 或 `workflow advance` 持续推进。保留现有检查、请求次数和未知状态不重复提交规则。

即使当前会话不能直接听音频，也先运行 `audio_qc` / `workflow inspect-audio`，完成能做的音轨、静音、真实转写、语音时间与差异检查；字幕关闭也执行。仅把真正缺少的主观检查交给用户。报告区分机器识别、人工/AI 修正与真实看听，不制造“听过”的证据。

新 `studio-1.1-tail-qc` 项目的原生声音口播也会按已审句尾、静音和可用的识别/VAD 证据安全裁尾；保留原速、内部停顿和原片，拼接及续接参考使用相同有效终点。严格主音轨、空镜和明确设计的结束镜头保留；旧合同不自动改时间轴。最终仍需完整真实看听。

## 2026-10-19 用户修正：不以报价作为制作前置条件

不主动要求查询、汇报或确认上游模型报价，不强制估算总费用。用户已确认制作范围后，即使没有单价、报价、计费单位、费用估算或账单接口，也直接继续已授权制作，不能因此停下来追问、要求“接受未知费用”或增加一次确认。不编造价格，也不把未知价格写成免费。若已有明确的开始制作指令，直接记录授权，不因费用重复询问。

默认按已确认的模型、素材、片段及请求次数执行。只有用户主动询价或明确提出金额上限时才处理费用；不得主动把金额上限加入普通方案或授权模板。已有用户明确设置的金额限制仍须遵守。追加片段、重做、改换模型等制作范围变化按用户授权处理，但不要求先报价。提交状态不明仍只查原任务，不自动重复提交。

## 2026-10-18 用户修正：自然表现优先

用户给出的时长默认仅作内容规划参考，最终以已确认口播稿、旁白和视频内容自然完成为准。新项目默认 `reference`；保留已调好的语速、音色、表情、动作和表演节拍，不因凑秒数修改它们。不得加慢或加快声音、拉伸人物动作、补空话或长停顿。只有用户明确要求必须精确达到时长或不能超过上限，才选 `exact` 或带上限的 `content-fit`。不能仅因自然成片短于参考时长要求重做。

## 2026-10-18 上线审查后的使用范围

先读 `references/release-readiness.md`。当前为受控试用版本：已有 Grok 旧入口三段真实口播候选，不能据此宣布全部模型或广告场景已上线验收。新入口的各模型、参考音色和严格音轨仍按各自账号进行首段与全片实际看听验收。

旧入口最终转写必须来自实听核对，逐字匹配确认稿（忽略标点、空白和大小写），不能只凭相似度或直接复制脚本通过；ASR 的繁简体和同音误识须结合实听人工修正。拼接报告记录实际时长；只有明确的硬性时长约束才阻断；媒体分析失败不能记为通过。旧版最终质检或脚本、时长、设置变化后，需要对已有视频重新质检，不需要因此重新付费生成。

## 2026-10-18 升级：先选择声音意图和执行入口

先读 `references/multimodel-production.md` 和 `references/studio-execution.md`。用户选择 `model_generated`（模型自由配音）、`reference_timbre`（参考音色）、`locked_audio`（严格使用全片音轨）之一。**模型支持参考音频也可以自由配音；素材库里有音频不等于用户选择使用它。** 不支持所选方式时说明限制，不擅自降级。

- 新入口 `scripts/production_plan.py`：免费本地生成模型能力快照、长视频/分镜计划、素材指纹和请求预览；可把已确认 PCM WAV 按真实句子时间码切分。没有上传或付费提交命令，输出 `execution_allowed=false`。请求编译涵盖 Wan 3、MiniMax H3、Seedance 2.5、Veo 3.1。
- 新执行入口 `scripts/studio.py`：记录已确认的制作范围后完成素材传输、创建/查询/下载、首段验收、断点恢复、逐段重做、口型、实际时间轴合成、字幕和交付。严禁绕过此入口直接提交离线 payload。详见执行指南。
- 严格声音使用 fal 托管口型适配，或先用可选 `scripts/speech_worker.py` 在已部署 CosyVoice/WhisperX 环境生成/对齐主音轨。开发未安装权重，也没有进行真实付费生成验收。
- 现有入口 `scripts/workflow.py`：继续执行已验证范围内的 Grok 网关流程。新增 `prepare --voice-mode model_generated`；参考音色、严格音轨在此入口明确拒绝。下文的旧网关参数、15 秒和 720p 仅适用于这一旧执行入口。rc6 新入口的原生声音裁尾按 automatic-quality.md 执行；严格主音轨仍禁止自动裁尾。
- 首段逐项检查改为 `{"status":"pass|fail|pending","observations":"具体观察"}`。失败、待检查和旧版纯文字记录均不能放行。旧报告需要对已有片段重新验收，不需要重新生成。
- 表演节拍上限改为每段最多 24 项，全片最多 10000 项；仍须每段与实际台词对应。新版模型规划使用独立的 3.0 算法，旧 1.0/2.0 合同不自动改写。

## 不可越过的边界

1. 内容理解、脚本、方案和材料分析只使用 Codex 自带能力，不调用外部文字模型。
2. 第一次回复不得生图。方案中先选定图片来源：Codex 会话有内置 `image_gen` 时默认使用，不要求另配图片 API Key；用户也可选已确认可用的自备人物图。仅在用户选择第三方图片接口且已配置时，使用本 Skill 的 `gpt-image-2` 路线。图片来源、提示词和用途必须写进方案；不要求报价或估费；来源变更须先更新方案。
3. 只有用户确认实际图片并明确说“开始制作”等同义指令后，才允许进入付费流程。
4. 新流程按确认的供应商/模型/输入模式选择适配器，不自动换模型。下列旧网关规则只适用于 `workflow.py`：视频默认首选 91topgo 的 `grok-imagine-video-1.5` 和其 `POST /v1/videos` + `GET /v1/videos/{id}` 异步协议；参考图使用已验收的 `reference_images`，本地生成图先压缩成不超过 800000 字节的 JPEG Data URI，再直接随视频请求发送。MikuAPI 的 `POST /v1/videos/generations` 仅作为显式降级。91topgo 不使用图片上传接口、不发送音频文件或 `reference_audios`；提示词生成人声仍需成片后本地复核。不得仅替换模型名或网址来接入其他模型。
5. 每个计划片段版本最多提交一次；重做须建立新版本并得到用户对重做范围的授权，保留历史。超时、断网或返回状态不明时，保留记录并停止，不得自动再发 POST。
6. 91topgo 只使用 macOS 钥匙串服务 `shuzirenskil-91topgo-video` 或 `SHUZIRENSKIL_91TOPGO_API_KEY`；MikuAPI 只使用 `shuzirenskil-mikuapi-video` 或 `SHUZIRENSKIL_MIKUAPI_API_KEY`。旧的通用变量 `SHUZIRENSKIL_API_KEY` 不再用于视频，防止把一家服务商的 Key 发给另一家。显式传入的 `.env` 未含对应专用变量时回退到该服务商的钥匙串。Codex 内置生图不读取 `OPENAI_API_KEY`；仅第三方图片路线使用 `OPENAI_API_KEY` 和 `OPENAI_BASE_URL`，模型固定为 `gpt-image-2`。密钥不写入 Skill、项目、日志、测试或报告，也不得混用。
7. 禁止新增字幕、标题、Logo、水印和 UI。普通口播默认全画面无字；广告中经用户确认的原有门头/包装文字与标识按 3.1 白名单保留在对应实体表面，逐字验收，不得与“禁止所有文字”同时要求。字幕只能在干净视频通过检查后本地制作。
8. 拼接完成不等于交付完成。最终必须同时通过技术检查、视觉检查、语音检查和拼接检查；广告还须通过实景空间、无静态拼贴、门店/产品保真与广告表达检查。
9. 用户上传的静态图只能作为生成参考，不能作为成片中的照片图层：禁止顶部照片条、分屏、画中画、静态照片插镜/推拉以及抠像贴图背景。必须由参考图与视频模型生成可信连续动态场景；候选预览也不能绕过，生成失败不得贴回原图补救。

## 获客广告先走专业场景设计

门店、公司服务、产品推广先读 `references/commercial-direction.md`。明确受众、一个主要价值、事实依据与行动邀请，再设计人物与门店/产品的同场景站位、光线、透视、动作和构图。用户要求人物站在指定门头前时，真实门头应在人物身后的空间里，不能改成泛化门店，也不能把原照片贴在画面上方。

广告新项目使用 3.1 创意合同和 `prepare --purpose storefront_ad|product_ad|company_ad`；普通口播保持 3.0。图片生成先携带原参考图重建完整场景，再用已确认生产图生成动态视频。图片只控制参考身份与空间，不作为剪辑层。审查/优化本 Skill 时只改规则、代码和离线测试，不据此启动素材或付费视频生成。

## 先判断任务类型

- **只有主题**：方向足够明确时，选择适合受众的角度并给出完整稿件和制作方案；用户指定时长就按目标写稿，未指定则按内容推算。只有缺少会明显改变内容的关键信息时才询问，不强制先选三五个方向。此时不生图。
- **稿件、PPT 或文档**：先检查事实来源、逻辑、口语感、平台风格、风险和时长，再给完整优化稿与制作方案。
- **门店、公司、产品图片**：先识别控制空间、品牌或产品的职责，读取广告指南，登记不可改变的结构、颜色、名称与原生文字；缺少场景信息不能凭空补成真实门店事实。
- **人物图片**：判断它控制人物身份、服装还是风格。确认用户有权使用其中人物形象。
- **只有音频**：先明确是参考内容、参考音色，还是严格保留整条声音；已有明确选择则直接按该选择规划。Grok 网关不支持自有声音上传；需要保留原声音时选择严格音轨加口型流程，不能默认换成模型自由配音。
- **字幕文件**：可作为内容参考，或在用户确认需要字幕时用于本地后期；绝不发送给视频接口。
- **已有口播视频**：默认走 `postproduction_only`，保留原视频和声音，不调用付费视频生成。只有用户明确要求重做数字人时才转为新视频方案。

材料涉及政策、产品参数、课程、企业流程或其他可核查事实时，先建立简短的事实表：来源位置、原文事实、脚本表达、验证状态。缺少依据的事实不能被润色成肯定说法。

## 两次确认流程

### 阶段 A：完整文字方案

先阅读 `references/voice-casting-and-text-review.md` 完成角色配音设计，再阅读 `references/duration-planning.md`，通过免费的 `plan` 反复检查草稿与时长，合适后再按 `references/proposal-template.md` 在主回复中提交完整方案。方案必须包含：

- 用户提供了什么，各材料控制事实、人物、声音、时长还是风格；
- 事实、逻辑、口语表达、平台风格和目标时长检查；
- 完整最终口播稿；
- 人物、服装、场景、镜头和画面运动；广告额外列出受众、核心价值、事实来源、行动邀请、空间关系、保真清单和静态拼贴禁用规则；
- 时长来自用户目标、用户上限还是内容推算；稿件可否改写；完整句子分段、每段预计口播秒数、请求秒数和预计交付时长；
- 本次准确的供应商、模型版本、输入模式、声音选择、时长与分辨率，以及文档/代码/模拟/真实样片各自的验证范围；
- 多参考图时列出每张图的顺序和唯一职责：`identity`、`wardrobe`、`product`、`scene`、`style` 或 `composition`，总数不超过 7，且至少一张为 `identity`；
- 旧 Grok 流程声音采用 `prompt_generated_voice`；新流程必须先确定三种声音选择之一。角色设计仍应用 3.0 的 `voice_casting` 先确定角色、设计依据和可听辨声音锚点，避免每次默认同一种男女声；再用结构化 `voice_profile` 锁定性别听感、年龄感、音高、音色、语速、情绪、发音和口音，并记录不随台词变化的 `voice_signature`；如使用预设声音则列出 `voice_id`。当前 MikuAPI 不使用 Files API，用户自己的音频不会上传；
- 结构化视频提示词中的视觉、镜头、表演、台词、声音、时间节奏和强制限制；
- 每段至少设计一个与真实台词短语对应的表演节拍，说明触发语、短暂表情、轻微手势和自然回位；只锁定声音身份，允许语调、语速和情绪随句意自然变化；
- 按参考时长设计大致内容量，优先保证口播稿、旁白和画面自然完整；不为凑秒数强行加减内容或修改已经优化好的语速与表情动作。表演节拍可只改变表情，不强迫每个短语都配手势。声音提示词不得写“前几秒说什么”等固定秒数分配；让语音自然决定停顿，画面跟随语义；
- 字幕默认关闭，或用户明确要求的本地字幕方案；
- 选定的图片来源（Codex 内置生图、自备图片或第三方 `gpt-image-2`）、真实生产图的用途、准确提示词；
- 基础付费次数、最高付费次数，两者必须相等；
- 停止条件和两次确认分别授权什么。

第一次确认只批准方案中选定的图片路线，不批准付费视频。

### 阶段 B：取得并检查真实生产图片

用户确认方案后，按已选来源取得图片：内置路线调用 Codex `image_gen`，把选中的真实结果保存到当前项目，再运行 `bind-generated-image --image-file <实际图片> --prompt-file <已确认提示词>`；自备图片使用 `bind-image`；第三方路线运行 `generate-image`，通过本机私密 `OPENAI_BASE_URL` 和 `OPENAI_API_KEY` 调用 `gpt-image-2`。内置生图不需要第三方图片密钥，但须确认当前会话确实有该工具；不可把账号登录本身当作工具可用或免费额度证明。图片工具不可用时先报告，不能静默改走收费接口。脚本会裁成视频画幅并绑定 SHA-256。`image-to-video` 的多段首帧只能从主图继续编辑；`reference-to-video` 的每张生产参考图必须单独展示、确认并绑定唯一职责，不能把预览分镜混进请求。不要生成写满方案文字的确认板。实际打开所有生产图核对可见造型、文字策略与声音选角；广告还须对照原图检查门店/产品和同场景构图，运行 `review-character`。把真实图片连同简明声音说明展示给用户，并等待原定第二次确认。不能从长相推断真实声音或籍贯。

第二次确认必须同时表达“确认这些图片”和“开始制作”。这一条回复同时授权已披露的短期图片上传、免费预检、已披露次数内的付费视频、尾部静音裁剪、拼接、质检和交付；不得再询问第三次确认。仅修正图片细节且脚本、模型、时长、付费次数、创意场景和文字策略均未变化时，不必重新确认整套方案；改换场景路线或原生文字白名单属于方案变更。

### 阶段 C：免费预检和制作

第二次确认后按 `references/workflow.md` 执行。先运行免费预检，确保脚本、模型、图片指纹、分段和付费次数与已确认方案完全一致；付费提交前再用当前服务商密钥免费检查目标模型是否可用。出现变化或免费检查失败就停止，不得静默调整。

## 长视频和分段

- xAI 官方文档说明 1.5 模型支持 1-15 秒；作者历史测试账号曾看到目标模型，并完成 4 秒、480p、9:16 与 15 秒、480p、16:9 单图短片的创建、查询和下载。新用户须用自己的账号重新检查模型可见性。15 秒 Provider 原片为 15.041667 秒，清理过长尾部静音后的交付版为 14.166667 秒；这证明单次 15 秒时长可用，不证明逐字台词、跨段连续性或更高分辨率。
- 2026-10-05 本项目还通过 91topgo 完成两次 15 秒、720p、9:16 人物参考图口播请求，原片均为 24fps；链路可用，但人物表演偏僵硬，不能把下载成功当作自然度验收。
- 用户给出普通时长要求时默认 `--duration-mode reference --duration N`，时长仅作内容规划参考；未指定时长则省略 `--duration`。只有明确“必须精确达到”才用 `exact`，明确“最长不超过”才用 `content-fit --duration N`。`auto` 仅保留旧合同兼容，不作为新任务默认。
- 15 秒只是单段上限。先按完整句子和自然语速寻找最少生成次数，再给每段分配实际需要的 1-15 秒；同一次请求不因补满 15 秒而省钱。目标模式会联合安排句子和秒数，例如 20 秒可以是 `10+10`，无需强制 `15+5`。默认估时 260 汉字/分钟，每段约 0.6 秒起音收声余量，整数秒取整也计入总时长。
- `plan` 根据完整稿件和原有语速估算自然时长，普通参考时长不会强迫补稿、删稿或改变表现。较大的偏差在方案中说明；仅明确硬性限制冲突时暂停讨论内容取舍，不能改动已确认稿和语速。
- 请求时长不等于最终交付时长；尾部静音清理可能使 15 秒原片变成约 14 秒的干净版。方案必须同时写清请求秒数、预计交付秒数和允许误差。
- 后期默认保持原速，不为凑整数秒自动拉长人物或声音。`exact` 项目若实际干净成片超出已确认误差，应如实标记未达时长目标并停止交付；调整脚本或重新生成须遵守用户对制作范围的授权，无需先查询或确认费用。
- `--duration-capability-test` 仍只用于明确的单片段 API 能力验收，不取代上述用户时长意图。
- **完整句子数量不等于视频片段数量**。多个相邻、完整的短句可以合并在同一个片段中；只有合并后预计超过约 14.4 秒，才开始新的片段。改写长句后必须重新计算和合并，不能直接“一句一段”。
- 例如三句稿前两句合计约 11.25 秒、最后一句约 6.66 秒，可为 2 段（12 秒 + 8 秒），而非 3 段；总请求是 20 秒，不能再声称满足“最长 19 秒”。
- 非最终片段必须在 `。！？!?` 等完整句子处结束。单个长句无法安全放入 15 秒时，先改写或请用户延长时长，不在半句话处切开。
- 91topgo 多段提示词人声默认复用同一组已确认的 `reference_images`；本地图片使用压缩 JPEG Data URI，公共 HTTPS 图片可直接复用。派生分段首帧只在用户明确接受人物与音色漂移风险后，通过 `--allow-derived-segment-images-with-risk` 使用。MikuAPI 旧路线继续遵守它自己的单图输入合同。
- 多段制作前阅读 `references/long-video-consistency.md`，固定人物、服装、场景、机位、灯光和动作范围。默认让模型按同一组声音提示词生成口播人声；即使提示词相同，也不能在未经真实听写验收前承诺台词、口型或跨段声音完全一致。
- 91topgo 的参考图请求复用带货视频 Skill 已验收的最多 7 张 `reference_images` 合同；用户自己的音频文件和 `reference_audios` 不发送，声音通过提示词生成并在本地复核。MikuAPI 的多参考图、预设声音和 `/v1/files` 仍保持关闭。
- 提示词和参考图只能提高音色一致性，不能保证一致。多段干净版质检必须真实听每一段和每个拼接点，并使用 `review --voice-consistency pass` 配合书面听感证据；Whisper 台词相似度不能代替音色检查。
- 多段项目默认先只提交第 1 段；下载后按原速完整看听，记录动作自然度、手势与台词是否对应、口型同步、声音、台词和人物身份，并运行 `review-pilot`。首段通过后才提交剩余已授权片段。试片不通过即停止后续付费请求，不自动重试或追加片段。
- 2026-08-24 已用用户确认的 16:9 人物图完成一次 1 秒、480p 提示词人声真实测试：只创建一次、不重试、未发送用户 MP3；成片有有效 AAC 人声和说话口型，本地 Whisper 准确识别“你好”。该证据只证明短句提示词人声可用，不证明能复刻用户音色或保证长视频一致性。
- 每段脚本、秒数、图片指纹和顺序写入生产合同。任何片段都没有自动重试额度。

## 字幕与质检

字幕默认关闭。用户在方案确认时选择字幕后，先检查无文字干净视频，再用本机 Whisper 取得时间信息，以确认后的口播稿作为字幕文字，最后用 FFmpeg 烧录。Whisper 识别结果不能静默替换确认稿中的数字、名称或结论。拼接前自动删除每段末尾超过 0.6 秒的连续静音，只保留约 0.3 秒自然收尾；句子中间停顿不裁。

先按 `references/voice-casting-and-text-review.md` 为各原片与最终成片运行 `inspect-visuals`，完整查看全片和所有取样（含真实末帧、片尾密集取样）。记录绑定当前视频的 `text_review` 后才能标记文字策略通过；3.1 广告按已确认原生文字白名单复核，并额外记录 `ad_review`；取样生成成功不能代替视觉验收。首段还须记录声音是否匹配角色，最终使用 `--voice-casting-match` 检查。

阅读 `references/quality-checklist.md`。视觉判断由 Codex 查看真实视频抽帧和拼接点前后画面，再把结果写入质检记录。只有 `delivery-manifest.json` 的 `status` 为 `pass` 才能说“交付完成”。
完整动态检查必须以正常速度播放全片；静态抽帧只能辅助检查身份和画面文字，不能证明动作自然或口型同步。拼接保持 Provider 原片帧率，不静默从 24fps 插成 30fps。
语速与停顿单独验收：`review` 保存音频静音统计作为线索，具备真实视听能力的 AI 应按正常速度完整检查并记录 `speech_pacing`；确实缺少能力时仅请用户补齐缺项。两处以上超过 0.75 秒的内部停顿必须重点复核；不能因技术时长合格就认定口播自然。

## 本地脚本

草稿规划入口是 `python3 scripts/workflow.py plan --script-file <草稿>`；正式项目入口是 `python3 scripts/workflow.py --project-dir <项目目录> <命令>`：

- `plan`：草稿阶段免费估时和分段，不要求项目目录；可不传时长，不写项目、不联网。AI 先根据结果修稿，再准备正式方案；
- `prepare`：广告额外传 `--purpose storefront_ad|product_ad|company_ad` 和 3.1 `ad_contract`；新数字人口播默认必须传 `--video-prompt-spec <JSON>`，且每段至少一个与真实台词匹配的表演节拍；用 `--duration-mode reference|exact|content-fit（auto 仅兼容旧合同）` 锁定时长意图，未指定时长可省略 `--duration`；记录规划版本，旧合同按旧版本复核；多段默认先验首段。`--allow-legacy-performance-plan` 仅供表演方案迁移，不绕过新项目的时长检查；
- `confirm-plan`：记录第一次确认；
- `bind-generated-image`：第一次确认后，把 Codex 内置生图的真实本地文件裁成视频画幅并绑定，不读取第三方图片 API Key；
- `generate-image`：仅在方案选定第三方图片路线时调用 `gpt-image-2`，裁成视频画幅并自动绑定；
- `bind-image`：绑定主参考图、可选派生首帧、预览分镜及其 SHA-256 血缘；
- `review-character`：绑定实际图片和声音方案的视觉选角检查，不增加用户确认轮次；
- `inspect-visuals`：免费生成全程取样、片尾密集取样和真实末帧检查清单，不自动判定通过；
- `authorize`：角色图片检查通过后，记录原定第二次确认和最大付费次数；
- `upload-inputs`：保留的 Files API 图片上传实现；当前 MikuAPI 实测为 404，默认配置会阻止运行，不上传用户音频；
- `preflight`：生成脱敏请求与生产合同，不联网；
- `submit`：多段项目首次只提交首段；首段质检通过后才提交其余片段，每段至多 POST 一次；
- `poll`：只查询已有 `task_id` 并下载，不创建新任务；
- `review-pilot --evidence-file <JSON>`：首段正常速度完整看听后记录动作、声音、台词、节奏及声音选角观察，并提交绑定视频的无文字证据、试片指纹和实际听写台词，通过后放行后续提交；
- `stitch`：本地规范化并拼接；
- `review`：生成技术检查，并强制保存抽帧、最终语音转写和逐项观察证据；
- `subtitles`：仅对已通过干净视频生成本地字幕版；
- `finalize`：所有必需检查通过后生成交付清单。

`confirm-plan` 和 `preflight` 会重新计算最少完整句子分段。如果方案被手工改成比算法更多的片段，会在任何付费请求前停止。

已有视频使用 `prepare --existing-video <path>`，基础付费次数必须为 0。
